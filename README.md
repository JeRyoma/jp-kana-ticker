# 🎈 일본어 놀이터 4.0 — 그림 단어에서 문장까지 (Taskbar Ticker RSS)

이 버전은 **히라가나를 어느 정도 읽지만 가타카나가 낯선 초보자**가 업무 시간 4~8시간 동안 Taskbar Ticker를 계속 보면서 익히도록 구성했습니다. **낱글자 암기 / 읽어볼까요? / 정답 가리기 / 문자 퀴즈는 전부 제외**했습니다.

일본어를 유치원 아이에게 소개하듯, `バナナ (바나나) · 바나나` 같은 쉬운 단어에서 시작해 같은 단어로 `これはバナナです`, `バナナがすきです`, `バナナをたべたいです`처럼 문장을 확장합니다. 실제 일본 어린이 교육과정을 복제한 교재는 아닙니다.

## 1. 하루에 무엇이 지나가나요?

**2026-10-22(1일차) 기준 총 130개 항목 = 단어 36개 + 문장·짧은 대화 94개.** 다른 날은 주제와 중복 제거 결과에 따라 숫자가 달라집니다(최소 80개 이상 테스트). 매 항목에 일본어 원문, **한국어 발음**, **한국어 뜻**이 함께 표시됩니다.

```text
🍌 バナナ (바나나) · 바나나
🍌 これはバナナです (코레와 바나나데스) · 이것은 바나나예요
🍌 バナナがすきです (바나나가 스키데스) · 바나나를 좋아해요
🍌 バナナをたべたいです (바나나오 타베타이데스) · 바나나를 먹고 싶어요
🍌 バナナをください (바나나오 쿠다사이) · 바나나 주세요
🍌 バナナをたべたい？ (바나나오 타베타이?) · 바나나 먹고 싶어?
🍌 うん、たべたい！ (응, 타베타이!) · 응, 먹고 싶어!
🍎 りんご (링고) · 사과
🐱 ねこ (네코) · 고양이
💬 はい、ねこです (하이, 네코데스) · 네, 고양이예요
```

위 예시는 이해를 위한 발췌이며, 실제 RSS는 단어·문장·복습·대화가 **교차로 순환**합니다. 후반부의 `🔁` 표시는 이전 단어 또는 문장 복습입니다. 새로운 단어와 문장뿐 아니라 익숙한 내용도 다시 섞습니다.

### 난이도 및 분량

- 그날 주제의 단어 10개(가타카나 5개 + 히라가나 5개)
- 앞뒤 주제에서 함께 볼 단어 10개
- 최근 배운 단어나 추가 생활 단어 16개
- 주제에 맞는 단어 활용 문장 약 50~70개 + 짧은 대화 + 복습 문장
- 간단한 문형: **이것은 ~예요 / ~ 좋아해요 / ~ 먹고 싶어요 / ~ 있어요 / ~ 어디 있나요 / ~ 주세요 / ~에 가요**
- 하루 한 주제씩 **평일에만 진도 증가**, 토·일은 금요일 진도 유지
- 20개 주제를 순환(과일, 동물, 음식, 집, 색깔, 준비물, 탈것, 놀이, 인사, 가족 등). 다음 순환에서는 단어의 등장 순서를 조정해 복습합니다.

일본어 원어민 발음과 한국어 음차는 일치하지 않습니다. 정확한 소리가 궁금하면 함께 제공하는 웹페이지의 **🔊 일본어 듣기** 버튼을 사용하세요(브라우저·운영체제에 일본어 음성이 있어야 작동).

## 2. 올릴 파일 구성

```text
jp-kana-ticker/
├─ generate.py                         # 날짜별 RSS와 학습 웹페이지 생성
├─ learning_data.py                    # 20개 주제의 단어·기초 문장 자료
├─ config.json                         # 시작일, 단어 및 문장 분량
├─ .github/workflows/publish.yml       # 평일 07:17 한국시간 자동 발행
├─ tests/test_generate.py              # 진도, 분량, RSS 검사
├─ docs/rss.xml                        # 전체(단어+문장+복습)
├─ docs/rss-words.xml                  # 단어 전용
├─ docs/rss-sentences.xml              # 문장·대화 전용
├─ docs/index.html                     # 모바일/PC로 복습하고 소리 듣기
├─ docs/.nojekyll
└─ README.md
```

압축을 풀어 저장소의 최상위 경로에 업로드합니다. **ZIP 자체를 GitHub에 업로드하는 방식이 아닙니다.** 특히 숨김 폴더처럼 보이는 `.github/workflows/publish.yml` 파일이 포함되어 있는지 확인하세요.

## 3. RSS 주소 실제로 만들기 — GitHub Pages

1. <https://github.com/new>에서 새 **Public** 저장소를 만들고 이름을 `jp-kana-ticker`로 정합니다. GitHub 사용자가 이미 `jp-kana-ticker` 저장소를 만들었다면 새로 만들지 마세요.
2. 이 ZIP을 압축 해제한 뒤 `generate.py`, `learning_data.py`, `config.json`, `.github/`, `docs/`, `tests/`, `README.md`를 모두 저장소 최상위에 올립니다.
3. 저장소의 **Settings → Pages → Build and deployment → Source**를 **GitHub Actions**로 바꿉니다.
4. **Actions → Publish Japanese word-and-sentence RSS → Run workflow**를 실행합니다. 저장소에서 GitHub Actions 사용 허용이 필요할 수 있습니다.
5. Actions의 `build`와 `deploy`가 성공한 후 주소가 열리는지 확인합니다.

```
https://<GitHub-ID>.github.io/jp-kana-ticker/rss.xml
```

예를 들어 계정 이름이 `example-user`이면 `https://example-user.github.io/jp-kana-ticker/rss.xml`입니다. **위 예시 주소는 실제로 배포된 사이트가 아닙니다.** 배포 후 아래 세 주소를 사용할 수 있습니다.

- **전체형(추천)**: `https://<GitHub-ID>.github.io/jp-kana-ticker/rss.xml`
- **단어 전용**: `https://<GitHub-ID>.github.io/jp-kana-ticker/rss-words.xml`
- **문장 전용**: `https://<GitHub-ID>.github.io/jp-kana-ticker/rss-sentences.xml`

프로그램의 RSS 항목 표시 개수 상한은 확인되지 않았습니다. 전체형에서 일부 내용이 보이지 않는다면 별도 RSS를 연결하거나 앱의 설정 및 갱신 상태를 확인하세요. 분리형을 각각 넣으면 표시가 보장되는 것은 아닙니다.

### 기존 GitHub 저장소를 이미 쓰고 있다면

원래 저장소 이름과 RSS 경로는 그대로 두고, **압축 파일의 내용을 기존 저장소에 덮어써 업로드**하면 됩니다. 교체해야 할 핵심 파일은 `generate.py`, `learning_data.py`, `config.json`, `.github/workflows/publish.yml`, `docs/`입니다. 예전 워크플로가 중복으로 남아 있다면 정리합니다. 새 Actions가 성공하면 기존 Taskbar Ticker의 `rss.xml` 주소를 그대로 사용할 수 있습니다.

## 4. Taskbar Ticker 설정

1. Taskbar Ticker를 열고 **Settings**에서 RSS 피드를 추가합니다(메뉴 명칭은 설치 버전에 따라 다를 수 있습니다).
2. 배포에 성공한 RSS 주소 하나를 먼저 넣습니다. 뉴스 RSS가 많다면 일본어 학습용 RSS를 집중해서 볼 수 있도록 다른 피드를 일시 비활성화합니다.
3. 글자 크기는 일본어가 또렷하게 보이도록, 속도는 단어를 한 번 눈으로 읽을 수 있을 정도로 설정합니다.
4. Taskbar Ticker의 제목을 클릭하면 같은 내용을 볼 수 있는 학습 페이지로 이동합니다. 온라인 페이지 주소는 `https://<GitHub-ID>.github.io/jp-kana-ticker/`입니다.

**주의:** Taskbar Ticker는 RSS 표시 프로그램이며, `rss.xml`에 들어 있는 항목을 **반드시 모두 표시하는지, 얼마나 자주 순환하는지**는 앱 구현/설정에 달려 있습니다. RSS 파일에서 실제 스크롤 반복 횟수나 속도를 강제하지는 못합니다.

## 5. 매일 자동 갱신 및 복습 원리

`.github/workflows/publish.yml`의 예약 시각은 `17 22 * * 0-4`(UTC)이며, **한국시간 월~금 07:17**입니다. Actions의 혼잡도 때문에 실행이 지연되거나 누락될 수 있습니다. 토요일·일요일에는 자동 새 진도가 발행되지 않습니다. 휴일 중 평일은 별도로 판단하지 않으므로 진도가 진행됩니다.

처음 설치하는 날이 이미 오후라면 Actions에서 **Run workflow**를 직접 눌러 오늘 학습 내용을 생성하세요. 생성기는 `config.json`의 `start_date`부터 **월~금만 카운트**합니다. 진도를 초기화하려면 `start_date`를 새 날짜로 바꿔 커밋한 뒤 실행합니다.

공개 저장소에서는 장기간 활동이 없는 경우 GitHub가 예약 작업을 비활성화할 수 있습니다. 이 경우 Actions에서 다시 활성화해야 합니다. 패키지에는 평일 생성물을 커밋하는 보완 작업이 있지만 항상 성공을 보장하지 않습니다.

## 6. 하루 분량 조절하기

`config.json`:

```json
{
  "start_date": "2026-10-22",
  "timezone": "Asia/Seoul",
  "extra_words": 16,
  "sentences_per_focus_word": 4,
  "sentences_per_companion_word": 2
}
```

- `extra_words`: 추가 단어 수. 늘릴수록 하루 단어와 복습 문장이 늘어납니다. 실제 단어 목록은 20개 주제 안에서 순환합니다.
- `sentences_per_focus_word`: 중심 주제 단어당 표기할 문장 최대 개수.
- `sentences_per_companion_word`: 함께 복습하는 주제의 단어당 문장 최대 개수.
- 값이 커도 실제로 마련된 예문이 더 적으면 그 수만큼만 표시됩니다.

**추가 변경이 필요하지 않다면 기본 설정을 권장합니다.** 너무 많은 제목을 추가하면 한 바퀴 돌아오는 데 시간이 길어져 오히려 같은 문장을 다시 보기 어려울 수도 있습니다.

## 7. 내 PC에서 테스트하거나 고장 확인

Python 3.11 이상에서 외부 패키지 없이 실행할 수 있습니다.

```bash
python -m unittest discover -s tests -v
python generate.py --date 2026-10-22
python generate.py --date 2026-10-24
```

두 번째 실행은 `docs/`의 파일을 테스트 날짜의 내용으로 덮어씁니다. 10월 24일은 토요일이므로 10월 23일과 **같은 학습일(2일차)**이어야 합니다. 업로드 전에 실제 날짜 기준으로 생성하려면 마지막에 `python generate.py`를 한 번 실행하면 됩니다. GitHub 배포 시에는 자동으로 당일 날짜로 생성합니다.

업로드 뒤 페이지가 404라면 Pages 배포 성공 여부를 확인하고, 티커에 오래된 내용이 나온다면 RSS를 브라우저로 열어 최신 내용인지 먼저 확인하세요. XML은 정상인데 티커에 반영되지 않는다면 앱의 새로고침·피드 캐시 문제일 수 있습니다.

---

**현재 제공 상태:** 코드·학습 데이터·RSS 샘플을 만든 것이며, 사용자의 GitHub에 실제 게시하거나 PC Taskbar Ticker에 연결한 것은 아닙니다. 설정 완료 여부는 GitHub Actions 배포 성공과 실제 RSS URL 접속으로 검증해야 합니다.
